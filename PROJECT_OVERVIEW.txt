1. WHAT IS JOBNITY?
--------------------------------------------------------------------------------

Jobnity is an AI-powered Career Readiness and Skill Gap Analysis Platform.
It helps job seekers understand where they stand against any target job role by:

  - Parsing their resume (PDF or DOCX)
  - Automatically extracting their skills, education, and experience
  - Comparing their extracted skills against a curated database of role-specific
    skill requirements
  - Generating a scored Skill Gap Report
  - Recommending learning resources (YouTube, articles, roadmaps) for missing skills
  - Providing skill-to-role roadmaps for career planning

The application is designed to be fully deployable on Vercel (serverless) with
no external paid API dependencies and no heavy ML framework requirements.

3. ACTUAL IMPLEMENTED TECH STACK (AND DEVIATIONS EXPLAINED)
--------------------------------------------------------------------------------

  Component         Proposed             Implemented            Status
  ---------------   ------------------   --------------------   --------
  Frontend          React.js             React 18 + Vite        MATCH
  Backend           Python + FastAPI     Python 3 + FastAPI     MATCH
  Database          PostgreSQL           SQLite (+ SQLAlchemy)  DEVIATED*
  NLP               spaCy                Regex + taxonomy DB    DEVIATED*
  ML / Embeddings   BERT / Sentence-BERT Token boundary match   DEVIATED*
  Skill Matching    Cosine similarity    Canonical normalization DEVIATED*
  Data Processing   Python               Python scripts         MATCH
  Resume Input      PDF / DOCX           pypdf + python-docx    MATCH

  * Deviations were intentional for the following reasons:

  DATABASE (PostgreSQL -> SQLite):
    SQLite was chosen for Vercel serverless compatibility. Vercel functions do
    not support long-lived TCP connections to PostgreSQL. The seeded SQLite
    database (jobnity.db, ~860 KB) is bundled with the project and copied to
    /tmp at runtime on serverless environments. Migration to PostgreSQL only
    requires changing the DATABASE_URL environment variable.

  NLP / ML MODELS (spaCy, BERT, Sentence-BERT -> Taxonomy Matching):
    Heavy ML libraries (spacy, torch, sentence-transformers) exceed Vercel's
    250 MB serverless function package size limit. The implemented approach
    uses an exact token-boundary taxonomy matching system with canonical skill
    normalization. This prevents false positives (e.g. "C" matching "C++",
    "JS" matching "JSON") while remaining fast, accurate, and serverless-safe.

7. DATABASE SCHEMA
--------------------------------------------------------------------------------

  The application uses a pre-seeded SQLite database with 7 tables:

  TABLE: job_roles (52 rows)
    role_id, job_role, category, sub_category, role_description,
    experience_level, common_alternative_titles, industry, source

  TABLE: skills (1,156 rows)
    skill_id, skill, category, sub_category, description, aliases,
    parent_skill, related_skills, prerequisite_skills, skill_type,
    technical_domain

  TABLE: skill_aliases (1,321 rows)
    alias, canonical_skill_id, canonical_skill, confidence
    (Maps alternate names to canonical skill names, e.g. "JS" -> "JavaScript")

  TABLE: skill_relationships (0 rows - reserved for future use)
    id, source_skill_id, source_skill, relationship_type,
    target_skill_id, target_skill

  TABLE: role_skills (527 rows)
    id, role_id, job_role, skill_id, skill, skill_category,
    importance (Required/Preferred), priority (1-5), minimum_level,
    frequency, skill_evidence
    (Maps which skills are needed for each role)

  TABLE: learning_resources (125 rows)
    resource_id, skill_id, skill, resource_type, title, url, provider,
    difficulty, description, duration, quality_score, relevance_score, verified

  TABLE: resumes (25 rows - seeded test data)
    resume_id, filename, file_path, file_type, file_size,
    raw_text, created_at

  TABLE: candidate_profiles (25 rows - seeded test data)
    id, resume_id, name, email, phone, education, experience,
    skills, projects, certifications, updated_at

  TABLE: skill_gap_analyses (4 rows - from live sessions)
    analysis_id, resume_id, role_id, target_role, skill_gap_score,
    readiness_score, matched_skills, missing_skills,
    preferred_missing_skills, statistics, created_at

8. CORE ALGORITHMS AND PROCESSING PIPELINE
--------------------------------------------------------------------------------

  8.1 RESUME TEXT EXTRACTION
      - PDF files: pypdf library - reads all pages and concatenates text
      - DOCX files: python-docx library - reads paragraphs and table cells
      - Result: Raw text string, cleaned of non-printable characters

  8.2 NLP PROFILE EXTRACTION (nlp_extractor.py)
      The NLPExtractorService processes raw resume text through:

      a) Section Detection (split_into_sections):
         Identifies document sections using header keywords:
         [education, experience, skills, projects, certifications, header]

      b) Name Extraction:
         Reads first 5 lines of the header section.
         Identifies 2-4 word capitalized sequences (not containing @ or digits).

      c) Contact Extraction:
         Email: regex pattern for standard email format
         Phone: regex for 7+ digit number sequences

      d) Skill Extraction (KEY ALGORITHM):
         - Loads all canonical skills (1,156) and aliases (1,321) from the DB
         - Builds a unified mapping: alias/skill -> canonical_name
         - Sorts terms by length (longest first) to prevent short-term false matches
           e.g., prevents "C" from matching before "C++" is checked
         - Applies word-boundary regex: \b<term>\b for multi-char skills
         - Applies strict boundary for single-char skills (e.g., language "R")
         - Also tokenizes the explicit "Skills" section for raw listed tokens
         - Returns list of canonical skill names found in the resume

      e) Education Parsing:
         Pattern matching for degree keywords (bachelor, master, phd, b.tech...)
         and institution keywords (university, college, iit, nit, mit...)
         Extracts degree, institution, and duration (date ranges).

      f) Experience Parsing:
         Identifies job title lines using role keywords (engineer, developer,
         analyst, manager, intern, scientist, etc.) and date ranges.
         Extracts role, company, duration, and description bullets.

      g) Projects & Certifications:
         Parses structured project blocks (name, description, technologies)
         and certification lines (name, issuer).

  8.3 SKILL GAP ANALYSIS ENGINE (skill_gap.py)
      The SkillGapService implements:

      a) Candidate Skill Normalization:
         User-confirmed skills are normalized to canonical form using
         SkillNormalizerService (which queries the skill_aliases table).

      b) Role Skill Fetching:
         Queries role_skills table for the selected job role.
         Each role skill has: importance (Required/Preferred), priority (1-5),
         and minimum_level.

      c) Skill Matching:
         For each required role skill, checks against all candidate skills:
           1. Exact canonical match (after normalization)
           2. Substring/superstring match with token boundary
              (handles "React" matching "React.js")
           3. Distinct Guardrail Check - prevents false positives:
              Java != JavaScript, Docker != Kubernetes, AWS != Azure,
              Python != PyTorch, C != C++, C++ != C#, React != React Native,
              SQL != NoSQL, HTML != CSS

      d) Weighted Scoring Formula:
         weight = priority * (1.5 if Required else 1.0)
         readiness_score = (sum of earned weights / sum of total weights) * 100
         skill_gap_score = 100 - readiness_score

      e) Result Categorization:
         - matched_skills: Role skills found in candidate profile
         - missing_skills: Required role skills NOT found (priority ordered)
         - preferred_missing_skills: Preferred role skills NOT found

      f) Persistence:
         Analysis result is saved to skill_gap_analyses table with a unique
         analysis_id (format: A_<8-char-hex>).

  8.4 LEARNING ROADMAP GENERATION (roadmap.py)
      - Fetches all missing skills from a saved SkillGapAnalysis record
      - Sorts by importance (Required first, then Preferred) and priority
      - For each missing skill, retrieves curated learning resources:
          * YouTube videos (resource_type = "YouTube")
          * Blog articles (resource_type = "Blog")
          * Roadmap guides (resource_type = "Roadmap")
      - Returns personalized recommendation list

     Contains: 527 role-skill mappings across 52 job roles

                  priority, minimum_level, skill_evidence

  4. job_roles_dataset.csv  (~14 KB, custom-curated)

15. KEY DESIGN DECISIONS
--------------------------------------------------------------------------------

  1. NO PAID APIs - The entire platform runs without any external paid service.
     No OpenAI, no Google Cloud NLP, no AWS ML. Pure local computation.

  2. SERVERLESS-FIRST - All file handling, DB access, and ML inference are
     designed to work within Vercel's 250 MB function size and /tmp write limits.

  3. USER IS SOURCE OF TRUTH - After NLP extraction, the user can edit their
     skill profile before analysis. The confirmed profile is what gets scored,
     not raw NLP output alone.

  4. EVIDENCE-BASED PROFICIENCY ENGINE - Rather than binary skill presence, the system
     extracts usage context (work experience, projects, certifications, education)
     to assign evidence-based proficiency levels (0-5 scale: No Evidence=0, Mentioned=1,
     Basic=2, Working=3, Proficient=4, Advanced=5) and tracks usage duration in months.

  5. MULTI-FACTOR ALIGNMENT FORMULA - Readiness Score (0-100%) is calculated from 5 factors:
     - Required Skill Coverage (45%)
     - Proficiency Level Alignment (25%)
     - Evidence Quality & Experience Duration (15%)
     - Preferred Skill Coverage (10%)
     - Transferable Skill Credit (5%)

  6. BELOW-LEVEL & TRANSFERABLE SKILL MATCHING - Differentiates complete skill gaps
     from skills present but below required level (`below_level_skills`), and awards
     partial credit for related candidate skills via `SkillRelationship` graph matching.

  7. PRE-SEEDED DATABASE & MIGRATIONS - Pre-seeded SQLite database (jobnity.db)
     with automatic table schema migration on startup. Includes a standalone
     data integrity validation script (`backend/scripts/validate_taxonomy.py`).

16. KNOWN LIMITATIONS AND FUTURE IMPROVEMENTS
--------------------------------------------------------------------------------

  CURRENT LIMITATIONS:
  - Database is SQLite (single-file). Under heavy concurrent load, this could
    become a bottleneck. Upgrade to PostgreSQL for production scale.
  - Learning resources are manually curated (125 entries). A web-scraping or
    API-based resource discovery pipeline would expand coverage significantly.
  - Resume uploads on Vercel are ephemeral (/tmp is cleared between invocations).
    Uploaded files are only needed for text extraction, so this is acceptable,
    but file storage (e.g., Supabase Storage, S3) would be needed for file history.
  - No user authentication. All sessions are identified by resume_id only.

  FUTURE IMPROVEMENTS:
  - PostgreSQL integration for production deployments
  - User accounts with OAuth (Google / GitHub)
